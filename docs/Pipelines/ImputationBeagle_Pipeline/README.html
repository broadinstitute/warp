Introduction to the Array Imputation pipeline​

The Array Imputation pipeline imputes missing genotypes from a multi-sample VCF using a large genomic reference panel. It uses Beagle for phasing and imputation. The workflow chunks each requested contig by position, validates each chunk against the reference panel, splits the chunks into sample batches, phases/imputes each sample batch, strips overlap regions, merges the sample batches back together, and emits per-contig imputed VCFs with QC summaries.

The pipeline is composed of two sub-workflows orchestrated by ImputationBeagle.wdl:

  1. ImputationBeagleCheckChunks splits the input VCF into position chunks (with overlaps) for each contig and validates every chunk against the reference panel.
  2. ImputationBeagleBatch phases and imputes one sample batch (designed to scale to approximately 1000 samples) across all pre-made chunks. It runs once per sample batch.

Because the input is chunked by position once and then split by sample (rather than the reverse), the position-chunk and reference-panel checks run a single time regardless of the number of samples. The version of each sub-workflow is tracked in its own changelog (CheckChunks, Batch).

Workflow installation and requirements​

The Array Imputation workflow is written in the Workflow Description Language (WDL) and can be deployed using a WDL-compatible execution engine like Cromwell, a GA4GH-compliant workflow manager that supports multiple computing platforms.

To identify the latest workflow version and release notes, see the Imputation workflow changelog.

Using the Array Imputation pipeline​

This pipeline is used by the All of Us + AnVIL Imputation Service. If you choose to use this service, you can impute your samples against the reference panel hosted in cloud storage.

Try the Imputation pipeline in Terra

You can alternatively run the pipeline with your own panel, using this WDL.

The auxiliary InputQC workflow validates the input multi-sample VCF before the imputation job runs. It checks chromosome compatibility, VCF structure, and basic reference-panel compatibility using the shared QC task library.

QC checks​

The QcChecks task performs the App/analysis-side validation for the input VCF, including checks such as:

  • VCF format version compatibility
  • contig compatibility with the expected reference assembly
  • absence of obvious array/WGS data issues that would invalidate imputation
  • basic structural checks for sorted/valid VCF records
  • compatibility with the reference dictionary and allowed contig set

Important notes​

  • Runtime parameters are optimized for Broad's Google Cloud Platform implementation.
  • The workflow fails early (in ImputationBeagleCheckChunks, before any imputation) when a chunk fails the reference-panel overlap QC, unless error_count_override is set to permit continuation.
  • When the input has more samples than sample_chunk_size, each position chunk is split into sample batches, imputed with allele probabilities, and merged after recomputing DR2/AF annotations. With a single batch, these merge steps are skipped.
