# CisMvSusie workflow guide

This guide describes [CisMvSusie.wdl](CisMvSusie.wdl) and its imported
[PrepareMvSusieInput task](PrepareMvSusieInput.wdl).
It documents the current implementation, including limitations; it does not change
the analysis or establish scientific validation.

## What the workflow does

For each selected gene, the workflow extracts genotype dosages within a cis window,
collects that gene's expression, splicing, and protein features, aligns samples,
adjusts for covariates, and fits a joint multivariate SuSiE model. It then writes
fine-mapping tables, plots, and cross-gene merged tables.

There are **no nested WDL subworkflows**. There is one top-level workflow, nine
locally defined task types, and one imported task type. R scripts called inside
tasks are processing steps, not additional WDL workflows or VMs.

The workflow starts from existing phenotype BEDs, covariate files, cis results, and
genotype dosages. It does **not** create those original datasets, calculate their
PCs, or run the upstream univariate cis association analyses.

## Execution and data flow

```text
Dosage + 3 BEDs + 3 covariate files + optional keep_samples
  -> CheckSamples ------------------------------------> shared sample list

Each original BED + optional gene_list/test_mode
  -> IndexExpression / IndexSplicing / IndexProtein ---> sorted BED + index + lookup

3 cis-result tables + indexed BEDs + selection settings + shared sample list
  -> BuildCisWindows ----------------------------------> selected gene/window IDs
                                                        association/target tables
                                                        cis_window_summary

For each selected gene/window:
  genome dosage/index + association table
    -> PrepareWindowGenotypes ------------------------> dosage TSV + window manifest
  indexed BEDs + association/target tables
    -> PrepareWindowPhenotypes -----------------------> combined BED + feature manifest
                                                        phenotype-preparation QC
  window files + 3 covariate files + shared sample list
    -> MvSusieInput.PrepareMvSusieInput ----------------> prepared matrix RDS + provenance
    -> FitMvSusie ------------------------------------> fit RDS + history + logs
      -> SummarizeMvSusie -----------------------------> 5 result tables
      -> PlotMvSusie ----------------------------------> PNG + PDF + plot RDS

Each of the 5 result-table types, across genes
  -> corresponding GatherTables call ------------------> merged TSV.gz
```

`CheckSamples` and the three BED-indexing calls have no dependencies on each other,
so they may run concurrently. `BuildCisWindows` waits for all four. Within a gene,
genotype and phenotype extraction can run concurrently; after fitting, summary and
plotting can run concurrently. Genes can also be processed concurrently.

For N selected genes, there are **10 + 6N task calls**, before retries/cache hits:
five setup calls, six calls per gene, and five gather calls. This is a task count,
not the number of VMs necessarily running at the same time.

## Workflow input reference

### Required data inputs

| Input | Meaning and expected shape |
| --- | --- |
| `genome_dosage` | BGZF-compressed wide dosage TSV. First four columns are `CHROM`, `POS`, `REF`, `ALT`; remaining columns are sample dosages. The extraction task accepts/removes a leading `#` in the header. Not a VCF. |
| `genome_dosage_tbi` | Matching tabix index for the dosage file. Contig names must agree with the selected windows. |
| `expression_phenotypes` | Expression BED: four metadata columns (chromosome, start, end, phenotype ID), then sample columns. Header must begin with `#`. |
| `splicing_phenotypes` | Same BED layout, with splice-feature IDs. Coordinates must not be assumed to be gene TSS coordinates. |
| `protein_phenotypes` | Same BED layout, with protein-feature IDs mapped to genes. |
| `expression_cis_results`, `splicing_cis_results`, `protein_cis_results` | One TSV or compressed TSV per modality. The cis builder requires `phenotype_id`, `pval_nominal`, and `qval`; splicing results can additionally provide `group_id` for gene assignment. |
| `expression_covariates`, `splicing_covariates`, `protein_covariates` | One wide covariate TSV per modality: covariates as rows, sample IDs as columns after the first identifier column. These are supplied, not generated by this workflow. |
| `docker_image` | Container reference used by every task. Must contain R/packages, tabix/bgzip, shell tools, and the analysis scripts under `/opt/mvsusie/scripts/`. |

### Selection and sample controls

| Input | Default | Actual behavior |
| --- | --- | --- |
| `keep_samples` | Unset | Optional sample-list file, intersected with samples present in all seven input data/covariate headers. |
| `gene_list` | Unset | File containing exact gene IDs, one per line. Overrides the q-value selection filter, but not feature-presence, TSS availability, or `max_genes` filtering. |
| `test_mode` | `false` | Restricts each BED to `gene_list` before sorting/indexing. Requires a nonempty list and at least one matched feature in each modality BED across the whole list. Does not stop before fitting or subset samples. |
| `qval_threshold` | `0.05` | Without `gene_list`, a gene qualifies initially when its minimum q-value across modalities is strictly below this threshold. Does not require significance in every modality. |
| `cis_window_bp` | `1000000` | Window radius around the gene-level TSS. |
| `min_modalities` | `2` | Minimum number of modalities with BED features, not minimum number with significant cis results. At least expression or splicing must be present, and expression/protein TSS coordinates must be available. |
| `max_genes` | Unset | If positive, retain at most this many eligible genes, ranked by minimum q-value then gene ID. No positive default cap. |
| `min_shared_samples` | `50` | Minimum initial header-based intersection. Not rechecked after per-window complete-case filtering. |

Gene-ID parsing is shared in intent across BED filtering and window construction:
expression uses the full feature ID, splicing uses the text after the final `:`,
and protein removes the prefix through the first `_`. Gene versions are not
stripped. Splicing cis-result `group_id` overrides parsing for those result rows,
but BED feature assignment still depends on the feature-ID naming convention.

### Model and runtime controls

| Input | Default | Meaning |
| --- | --- | --- |
| `start_L`, `step_L`, `max_L` | `10`, `5`, `40` | Try component counts 10, 15, ..., 40 until the greedy stop condition is met. |
| `greedy_lbf_cutoff` | `1.0` | Stop increasing L when the minimum component log Bayes factor is below this value. |
| `max_iter` | `100` | Maximum fitting iterations per greedy round. |
| `tol` | `0.0001` | Convergence tolerance passed to mvSuSiE. |
| `coverage` | `0.95` | Requested credible-set posterior coverage; not a measured validation accuracy. |
| `min_abs_corr` | `0.5` | Credible-set purity filter passed to SuSiE utilities. |
| `min_genotype_variance`, `min_phenotype_variance` | `1e-8`, `1e-8` | Despite their names, the current preprocessing script compares **standard deviations**, not variances, against these thresholds. |
| `n_thread` | `1` | Thread setting passed to mvSuSiE. Does not change the WDL's fixed CPU request. |
| `mashr_n_pca` | `5` | Requested PCA covariance components for learning the mashr prior. |
| `mashr_strong_lfsr` | `0.05` | Strong-association selection threshold used during prior learning. Not a global output significance filter. |
| `mashr_seed` | Unset | Optional seed passed to prior learning. |
| `include_canonical_priors` | `false` | Adds mashr canonical cross-outcome covariance patterns alongside the learned PCA covariances. |
| `use_mashr_null_weight` | `false` | Uses mashr's estimated all-outcomes-null weight in the mvSuSiE prior instead of forcing it to zero. |
| `fit_memory_gb` | `16` | Memory request for `FitMvSusie` only. |

### BuildCisWindows details

1. Read cis results and assign genes. Missing/unparseable q-values and nominal
   p-values are replaced with 1 in the current implementation.
2. Use supplied gene IDs, or select genes with minimum q-value below the threshold.
3. Count BED features per gene and modality. Require the configured number of
   modalities, expression or splicing presence, and a gene-level TSS source.
4. An explicitly listed gene without expression/protein coordinates causes an
   error. Other genes without an anchor are excluded with a log message.
5. Rank eligible genes by minimum q-value, then gene ID; apply positive `max_genes`.
6. Use expression coordinates preferentially, otherwise protein coordinates.
   The BED `end` is interpreted as the 1-based TSS. Splicing coordinates never
   anchor a window. Conflicting gene-level coordinates produce a warning; the
   first available expression/protein coordinate is used.
7. Store each interval as 0-based half-open:
   `start = max(0, TSS - cis_window_bp - 1)`, `end = TSS + cis_window_bp`.
   Tabix genotype extraction queries `start + 1` through `end`.
8. Write an association row for every selected BED feature. Its compatibility
   p-value comes from its own nominal result, otherwise the best nominal result
   for that gene/modality, otherwise 1, clamped to [0, 1].
9. Write expression/splicing target rows separately because the reused trans
   preparation script expects that contract. The `trans` names refer to the
   reused interface, not a trans analysis in this workflow.

The phenotype task applies a top-N cap of 100000 per modality to association-based
selection. Expression/splicing features are also supplied as targets. This is
intended to retain all ordinary per-gene feature sets, not a small top-N panel.

### PrepareMvSusieInput details

The [imported task](PrepareMvSusieInput.wdl) is the bridge from tabular window
files to the matrices consumed by mvSuSiE:

1. Read the one-window manifest, feature manifest, dosage, combined BED, and three
   modality-specific covariate files.
2. Align sample rows by normalized IDs, preserving genotype sample order, and
   restrict to the shared sample list.
3. Remove a sample if any selected genotype, phenotype, or supplied covariate
   value is non-finite. No missing-value imputation is performed here.
4. Remove unusable raw phenotypes by their standard deviation.
5. Apply rank-based inverse-normal transformation to each retained phenotype.
6. Build a union of the three aligned covariate matrices for genotype adjustment.
   Same-named identical covariates are deduplicated; same-named differing
   covariates receive modality-qualified names. Add an intercept and residualize
   the genotype matrix against this union.
7. Residualize each outcome against its own modality's covariates plus intercept.
8. Filter low-standard-deviation residualized outcomes and genotypes. Center and
   scale retained residualized outcomes to unit variance.
9. Save sample-by-variant `X`, sample-by-outcome `Y`, metadata, sample IDs,
   genotype covariates, ranks, input checksums, and preprocessing QC in the RDS.

The union covariate model for genotypes and separate modality models for outcomes
are intentional differences. This stage does not generate replacement original
covariate TSVs.

### FitMvSusie details

The current container scripts calculate marginal SNP/outcome associations and
learn a joint mashr prior for that window. By default, the prior uses PCA-based
covariances and forces the mvSuSiE null-component weight to zero, matching the
original behavior. The two optional switches independently add mashr's
canonical cross-outcome covariance patterns and/or use mashr's estimated null
weight. Canonical covariances are generic patterns across outcomes, not
annotation-based variant priors. Prior learning is per gene/window, not pooled
across every gene.

The fit metadata records the selected prior mode, the number of PCA/canonical
covariances, mashr's estimated null weight, and the null weight actually passed
to mvSuSiE. The per-window QC table also records the prior name, canonical
covariance count, null-weight switch, estimated null weight, and applied null
weight. Enabling either switch requires rebuilding the Docker image with the
updated `fit_window.R`, model/prior scripts, and `trans_window_prior_modes.R`;
with both switches false, no additional command-line options are sent.

Fitting uses standardized predictors, no additional model intercept, fixed
initial residual covariance from the prepared outcomes, and fixed learned prior
variance/mixture weights. The previous fit initializes the next greedy round.
Nonconverged rounds and non-finite fitting results cause errors.

The greedy loop stops when the minimum component log Bayes factor is strictly
below the cutoff (`action = saturated`) or when the maximum requested L is reached
(`action = maximum`); other rounds have `action = continue`.

### Every GatherTables instance

All five instances take `files` (the corresponding per-gene summary output array),
`window_ids` (the matching gene array), and `output_name`. They check array lengths,
decompress tables, retain a single header, add `window_id` if absent from the first
nonempty table, concatenate rows, and gzip the result. They do not refit models,
deduplicate signals across genes, or perform cross-gene significance correction.

## Resource requests and scaling

All tasks use the supplied container and request a 30-GB boot disk.

| Task type | CPU | RAM | Task SSD |
| --- | --- | --- | --- |
| `CheckSamples` | 1 | 4 GiB | 100 GB |
| `PreparePhenotypeBed` (three instances) | 2 | 16 GiB | 200 GB each |
| `BuildCisWindows` | 2 | 16 GiB | 100 GB |
| `PrepareWindowGenotypes` | 2 | 16 GiB | 500 GB |
| `PrepareWindowPhenotypes` | 2 | 16 GiB | 500 GB |
| Imported `PrepareMvSusieInput` | 2 | 16 GiB | 500 GB |
| `FitMvSusie` | 2 | `fit_memory_gb` GiB (default 16) | 500 GB |
| `SummarizeMvSusie` | 2 | 16 GiB | 500 GB |
| `PlotMvSusie` | 2 | 16 GiB | 500 GB |
| `GatherTables` (five instances) | 1 | 4 GiB | 50 GB each |

No task requests a cluster or GPU. Runtime requests do not impose a dollar budget
or wall-clock timeout. Gene count controls scatter size; per-gene runtime depends
on samples, variants, outcomes, and fitting complexity. Full inputs may still be
localized repeatedly, including dosage in genotype-extraction tasks.

`test_mode` reduces BED sorting/output size, but does not avoid reading/localizing
the original BEDs, reduce resource requests, subset dosage in advance, filter
cis-result tables before reading them, or stop before model fitting.

For a one-gene run, use a one-line gene list plus `test_mode = true` and
`max_genes = 1`. Submit a single workflow, not a Terra batch over many table rows.

## Current caveats to keep in mind

- **Three QC rows can represent one fit.** The current summary script converts a
  QC list containing a three-element `phenotype_covariate_rank` vector directly
  to a table. Scalar fields repeat across three rows; ranks are ordered
  expression, splicing, protein without an explicit modality column.
- **Purity reporting needs care.** The summary code reduces the values of a
  returned purity row into `purity_min`/`purity_mean`, rather than explicitly
  extracting named minimum/mean absolute-correlation columns. Do not equate
  those exported fields directly with the `min_abs_corr` setting.
- **Initial sample minimum is not a final complete-case guarantee.** All seven
  input headers participate in the initial intersection even for genes lacking
  a modality. Later missing-value filtering can reduce sample count further.
- **A no-protein single-gene test currently fails in test mode.** Each BED-indexing
  call requires at least one matched feature. This is a restriction on the
  entire gene list per modality, not a requirement that every listed gene have
  every modality.
- **Gene-list selection does not bypass all filtering.** Exact ID matching,
  modality availability, TSS availability, and a positive `max_genes` still apply.
- **Gene-level coordinate disagreements warn rather than fail.** Check
  `n_distinct_tss` and the selected coordinate in `cis_window_summary`.
- **Some shell decompression paths suppress errors with `|| true`.** Existing
  nonempty/uniqueness checks are not a complete guarantee against truncated
  input or gather output. Successful execution alone is not data validation.
- **Plot backgrounds may be transparent.** If labels disappear in a dark viewer,
  view the PDF on white or render with a white background.
- **Script behavior depends on the container.** R-processing descriptions here
  were checked against the local
  [warp-tools script copy](../../../warp-tools/3rd-party-tools/aou_mvsusie/scripts/).
  A published image can contain a different revision. Retain the exact image
  digest and package/script provenance for reproducibility.
